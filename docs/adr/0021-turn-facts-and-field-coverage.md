# 0021 — Turn facts computed once, field coverage tested, filters by tool, model and outcome

**Status:** accepted (implemented)
**Builds on:** [0012](0012-prompt-index-and-stats.md) (prompt index), [0017](0017-connector-capabilities.md) (capabilities), [0020](0020-model-call-usage-and-version-capabilities.md) (model-call usage)

## Context
A Codex prompt ("hello", gpt-6-luna, Codex 0.167.0) showed no model and nothing saying it came from Codex on the Prompts page, while Claude Code rows showed "Opus 5.5" and a cost. Two causes:

1. **The model.** The prompt row read the model from `summary.models`, which only model calls (telemetry `api_request`, or Codex's `PostModelRequest`) fill. Codex reports its model on every hook payload (`fields.model`), and the index already counted that prompt for that model (ADR-0020 follow-up `a063014`), but the row never looked there. Each page picked its own fields (`summary.models`, `summary.cost_usd`, `fields.permission_mode`...), so a fallback added in one place was missing in the others.
2. **The tokens.** The prompt's `PostModelRequest` was stored with its `token_usage` and joined the turn by `turn_id`, after the `Stop`. The usage mapping that reads it (ADR-0020) is right: on a copy of the database, the current code gives the turn 14,842 tokens. The daemon that served the page had been started before that code (14:58 against the 16:26 commit), and the daemon reads Python code once at start, so it had no `usage` block for Codex. Restarting it is enough; nothing is to re-ingest, since everything is derived on read.

Nothing checked that a connector's pages show what its spec says it can report, or that a field a tool sends is used at all: a new field from a tool update was stored and never shown.

## Decision
1. **Facts, one block per prompt** (`insights/facts.py`), computed on the server from the prompt index row and the spec, with no `if source == ...`: `connector` (spec id, `name`, `short_name` as the badge `label`, `assistant`), `model` and `model_source` (the model that answered: the model of most *main-thread* model calls, a tie going to the one called last, else the one the hooks reported; background work such as titles, web search helpers and summaries, and subagents, never decide it, since they often run another model and can outnumber the main thread's calls), `models`, `tokens` (input, output, cache read and write, reasoning, total) and `cost_usd`, both **null** when no model call reported them (never 0; a cancelled Codex call has no counts, so no tokens either), `api_requests`, `outcome` (the SQL `OUTCOME`), `permission_mode`, `tool_version`, `response_s`, `answered`, and the turn's tool calls, failures, files written, commits and subagents. The prompt list and detail, session and project stories, search hits and exports all read it. New index columns (`model`, `permission_mode`, `tool_version`, `reasoning_tokens`, `answered`) let stories and search build the same facts from the index; the rules version rebuilds the index on first use.
2. **The dashboard shows facts only** (`web/src/lib/prompts/facts.ts` `factsView`): a tool badge (plug icon and short name, neutral ink, never colour alone: lagoon and iris stay "you" and "the agent"), the model through `modelName` (now also GPT ids: `gpt-6-luna` → "GPT-6 Luna"), tokens and cost when reported, and, when a turn has no tokens, why (`missingTokens`, from the capabilities helper: needs version X, connect a layer, the tool can't, or none reported for this turn).
3. **Every payload key is used or declared unused.** Specs get `ignored: {key: reason}` (keys GitPrompt deliberately leaves unused) and `shown: {key: where}` (keys the dashboard reads from the raw payload itself), shared ones in `_defaults.yaml`. `tests/sources/test_field_coverage.py` replays each connector's fixtures, records every key the derivations read (a traced payload), and fails on a fixture key that is neither mapped (`map`, `usage`, origin `path`), derived, shown nor ignored. A key read into (`token_usage` → `token_usage.input_tokens`) covers only what was read. Its first run found 14 unused keys across Codex and Copilot; they are now derived (tool errors, subagent tasks and results, compaction triggers, Copilot's reported errors, model call statuses) or ignored with a reason (`tool_response`, `stop_hook_active`, `token_usage.total_tokens`, `agent_transcript_path`, Copilot's `timestamp`, `tool_result`, `agent_name`, `custom_instructions`). The Fields page marks ignored fields with their reason.
4. **A display contract** in the conformance kit (`test_prompts_show_what_the_connector_can_report`): for each connector's fixtures, through the API, every prompt names its tool; with `model` every prompt has one; with `usage` some prompt shows tokens; without `usage` or `cost` none shows them (null, not 0); with `answer`, `turn_end`, `tools` the answer, an end and tool calls appear; the list and the detail agree.
5. **Filters by tool, model, outcome and project** on the Prompts page: the Overview's selects became one component (`lib/insights/FacetSelects.svelte`, `FACETS`/`facetChoices` in `filters.ts`), each choice counted with the other filters by `/api/stats`, in the URL, so the Overview's `promptsHref` links land on the same selects. `/api/stats?group_by=source` names each tool (`detail`, from its spec). A link that sets several values of one filter keeps them as removable chips.

## Consequences
- A new connector gets a badge, model, tokens and filters from its YAML: `short_name`, `capabilities`, `usage`, and its fixtures. Its fixtures must account for every field it sends, and the display contract checks the pages against its capabilities.
- A tool update that adds a field fails the coverage test once a fixture carries it: map it, derive it, or add it to `ignored` with the reason.
- Users must restart a daemon started before a code change to see it (true of every derived value; documented in the README).
- Not done: a per-event `ignored` (a key is ignored for every event of a tool), and outcome in the dashboard still recomputes `running` with the browser clock for live rows.
