Rules every ticket follows (from CLAUDE.md)

  • Lowest crate first. Pure logic goes in gitprompt-insights or gitprompt-core, storage in gitprompt-store, HTTP in gitprompt-server. No ticket adds a crate or an edge between crates; just arch stays green.
  • The wire type lands first. A backend ticket's first commit is the Rust type with #[derive(TS)], added to roots() in tests/ts_types.rs, then just types. The web ticket that needs it starts from that commit against a fixture, so the pair overlaps. Every new read endpoint gets a snapshot (just snapshots), read before accepting.
  • Time is injected. Anything about "now", "this week" or "running" takes the server's Clock or the page's shared clock. Tests use FixedClock, ManualClock or fake timers; never sleep (just timing).
  • Small parts. Functions under 80 lines and complexity 15, files under 500 (Rust) or 400 (web). A new component is shown on /design in the ticket that adds it.
  • Replace, then delete. A ticket that replaces a component moves its users over. The phase's quality ticket deletes what has no user left; nothing lives on as a wrapper.
  • Count the new action. A new copy, open or command calls track() with a name added to the closed list from 01, so each "It worked if" has a number.
  • Native only where it pays. A Tauri feature is added when it makes something faster or removes a step, never for looks. The decision is a pure function in gitprompt-tauri; backend/apps/desktop only draws. The page reaches it through web/src/lib/platform/ (11), which also answers in the browser, so the web build never changes. A new plugin asks first, and idle CPU with the window hidden stays at the baseline.
  • No silencing. No eslint-disable, @ts-ignore or any; no new entry in COMPLEX; no line added to the timing ledger.
  • Nothing is lost. Every ticket that moves a feature keeps it reachable (§08 checklist). Old URLs keep working or redirect.

Rules for a chart

  • A question, then a sentence, then the chart. The title is the question, one sentence states the answer from the numbers, and the chart is the proof.
  • Every mark is a doorway. A bar, a square or a tick opens the prompts, the day or the session behind it, through links.ts, and the click is counted (01).
  • One colour, one meaning. Outcome colours come from one module (34); a project keeps its colour on every page.
  • What exists is kept. The table view, keyboard readout and tooltips of today's charts stay; a moved chart loses nothing.
  • Shown where the decision is. The week belongs on the first screen, the year on Activity, a turn's timeline inside the turn. A chart nobody opens (usage counts) is a candidate for removal after M6.
